# Data scan for the Cash Overwatch pillar (7 Nov 2026)

What the MIS server stores or can compute today, against what `GET /api/tally/summary` (`connectors/tally/ceoSummary.ts`,
MCP `mis_get_summary`) already gives. "Computable today" = from stored snapshots only (no Tally call, no connector pull).
Everything here is READ ONLY.

## Already in the summary (v1)
Per month (last 13): sales, other income, purchases, direct / indirect expenses (TB FY-to-date differences), Nett Profit
and closing stock (P&L copy), cash & bank, overdraft, net cash, debtors, creditors, loans, GST net (TB balances), TB
difference; the newest month's 12 biggest expense ledgers; notes.

## Store by store

### `tally/pnl-<YYYY-MM>` (P&L copies, `tally/pnl.ts`, `snapshots.ts`)
Fields: `ledgerRows[{name, amount}]` (shown sign: expense +, contra −, Closing Stock +), `nettProfit`, `asOf`, `warnings`.
Not in v1 → metric:
- ledger name → **sales channel** (Amazon / D2C / Flipkart / Blinkit / GT / B2B / Export) → `channels` block, monthly
  sales per channel, MoM. Mapping = the seed map + ledger rules the tie uses (`client/src/data/monthClose/ledgerMap.ts`,
  `ledgerRules.ts`); server copy of the name patterns in `ceoSummaryV2.ts`. **Computable today.** A combined "Ecommerce
  Sales" ledger stays Amazon (never split) — same rule as the close.
- ledger name → **cost bucket** (employee, marketing, channel fees, logistics, rent & factory, professional, finance,
  depreciation, other) → `costs` block, per month, MoM, % of sales. **Computable today.**
- `asOf` vs month end → `close.pnlCopyAt`, `daysAfterMonthEnd` (the 5-day rule the slot already warns on). **Today.**
- any ledger's monthly amounts → `mis_get_ledger_trend?ledger=`. **Today.**
- biggest ledgers of ANY month (v1 = newest only) → `mis_get_expenses?month=`. **Today.**

### `tally/tb-<YYYY-MM>` (Trial Balances, FY-to-date, `tb.ts`)
Fields: `rows[{name, level group|ledger, debit, credit}]`, `difference`, `basis`, `asOf`. Groups + exploded ledgers.
- **Balance sheet** per month via the statements builder (client `data/statements/statements.ts`, pure; ported to
  `connectors/tally/statementsCore.ts`): equity, liabilities, assets, cash per bank ledger, OD, FY profit, working capital.
  **Today** (masters `parents` improve the nesting when stored).
- **Indirect cash flow** month vs month: operating / investing / financing / retained / other / Δ cash. **Today** where two
  consecutive TBs exist.
- **FY-to-date P&L** from the group closings: sales, COGS (Purchase Accounts + Direct Expenses + Opening Stock − closing
  stock), gross margin, EBITDA proxy (FY profit + depreciation + finance-cost ledgers), net profit. **Today.** Last FY to
  date needs the TB of the same month a year earlier: the poll back-fills 13 months, so it is usually there; null otherwise.
- `difference ≠ 0` → `watch` "TB not tying". **Today.**

### `tally/masters`, `tally/books-<YYYY-MM>` (`books.ts`, `bookStore.ts`)
Masters give group → parent (used as `parents`). Day Books could give: payments made / received per month, biggest
payees, cheques pending — **not used yet** (voucher shapes UNVERIFIED until the first live pull, per CLAUDE.md).

### Chart of accounts (`chart.ts`)
Hanging ledgers count → already in `mis_get_accounts_issues`; not repeated.

### Ledger rules (`tally/ledger-rules`)
Stored regex rules for Blinkit / Flipkart sales etc. The server copy applies the DEFAULT patterns; a stored custom rule is
honoured when loaded (`rules` input). **Today** (defaults) / partial (custom rules need the loader to read the doc — done).

### Close locks (`close-locks`, `ingest/closeLocks.ts`)
`locks[period]{lockedAt, lockedBy, worstResidualPct, overrideReason}` → `close[].status` locked, `tieResidualPct`,
`breach` (> 1 %), `overrideReason`. **Today.** For an unlocked month the live tie residual is computed in the browser
(`closeTies.ts` on the deck) — the server has no engine run; it reports the **channel-sales gap** instead (below).

### Committed reports (`ingest/*/extracted.json`, `readAllExtracted`)
`connectorId|slotId|periodKey` + `payload.facts` (DailyFact: source, channel, date, revenue, gmv, netExGst).
- `MANUAL_SLOTS` (issuesInbox.ts) missing for a month → `close[].missingUploads`. **Today.**
- connector sales per channel (ex-GST like `closeTies.connectorSales`: netExGst, else gmv ÷ 1.18 for Shopify / Amazon,
  else revenue) vs Tally's channel ledgers → `close[].channelGap` ₹ per channel and total. **Today** for months with
  committed facts.

### Facts cache (`facts-cache/<source>-<YYYY-MM>`, `factsCache.ts`)
Same DailyFact shape for the live connectors (shopify, amazon, flipkart …) when the Live MIS has loaded the month. Used
as the fallback when no report is committed for source + month (the committed one wins, as in `buildLiveDeck`). **Today**
when present; a month never opened in the Live MIS has none (gap, not 0).

### Live MIS deck (`client/src/data/misDeck/*`, normalised COGM `liveViews.ts`)
Computed in the browser only (cascade, normalised COGM, CM1–CM3, SKU P&L). **Needs new work** to run server-side; not
in this change. The FY block uses Tally's own groups instead (as booked, not normalised).

### Price floors live (`services/priceFloorsLive.ts`)
Amazon unit economics from Ops BigQuery, cached 6 h in `price-floors-live` — already an MCP tool; not a books metric.

### Issues inbox (`services/issuesInbox.ts`)
Already an MCP tool. `MANUAL_SLOTS` reused for the close block.

### Planning scenarios
Plan outputs are computed in the browser; nothing stored to compare actuals against. **Needs new data** (a stored monthly
plan) for plan-vs-actual.

### Amazon stock valuation (`routes/stock.ts`)
Live BigQuery query + Production costs, cached 30 min in instance memory only — no stored snapshot. **Not cheap to read
from a stored copy** → skipped in the summary (`amazonStock: null` with a note). Needs a stored month-end snapshot.

## Watch rules computable today
Cash runway (3-month average net outflow), debtors +20 % MoM, creditors > 2 × monthly purchases, GST payable spike,
tie breach (locked months), TB not tying, a channel ledger −25 % MoM, P&L copy > 5 days after month end, missing manual
uploads for last month.
