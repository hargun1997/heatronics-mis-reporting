Tranzact and the TranZact Chrome plugin

Tranzact is where we raise invoices and record bills. The Chrome plugin is the bridge that turns approved Tranzact documents into Tally vouchers.

The concept

Document in Tranzactrules pick ledgers →Accounting entry (draft)approve →Approved queueChrome plugin sends →Tally voucherstatus back →Completed
  • Tranzact decides the ledgers, not Tally. Every document is turned into an accounting entry using Accounting Rules (which sales or purchase ledger) and Ledger Settings (tax, discount, round-off, TCS and journal ledgers).
  • Nothing moves until it is approved. Documents wait in Document Approval, journals in Journal Entry.
  • The Chrome plugin talks to Tally directly. It connects to the Tally On Cloud server, so Tally must be open. It sends one voucher type at a time. With "Check TDL & Duplicate Vouchers" on, it won't send a voucher that already exists.
  • Ledger names must match exactly. If a ledger named in Tranzact doesn't exist in Tally, the push can fail or a stray ledger can appear.

S2

tally-integration.in (the plugin website)

The vendor's website. It is the plugin's control room: it stores API keys and mapping rules, and holds the Amazon files until Tally pulls them.

The concept

  • Two workspaces. Store / Gateway holds direct API connections (Shopify, Easebuzz; a Shiprocket API mapping exists but is not used; there are no Snapmint settings on the site, so its mapping lives inside the TCP). Marketplace holds Amazon (and any marketplace), where data arrives as uploaded Excel reports.
  • Mapping rules are templates. Every field of a voucher (number, date, bill reference, ledger) is built from the source data with {{key}} placeholders, plus an optional regex. For example, bill ref {{tags}} with regex (?<=pg:)[^,\s]+ takes the text after pg: in the Shopify order tags.
  • Ledger names are typed as free text. Tally uses them by exact name; a name that doesn't match an existing ledger is the likely source of new near-duplicate ledgers. That is why near-duplicate ledgers appear, such as IGST 5.00% next to IGST Output - 5%.
  • Amazon uploads are stored per company, month and report type until option 2 in Tally pulls them.

S3

eCom2Tally plugin inside Tally (the TCP)

A Tally add-on (a .tcp file) that adds the "tally-integRation.in" menu. It is what actually creates vouchers for Shopify, Easebuzz, Amazon, Shiprocket and Snapmint.

The concept: every import does the same five things

1 · Read source rows→2 · Apply mapping rules→3 · Create missing ledgers / items (by exact name)→4 · Build voucher + bill refs→5 · Post to Tally
  • Where it reads from depends on the option. Option 3 calls the Shopify / Easebuzz API through the website. Option 2 downloads the Amazon file you uploaded to the website. Option 5 reads an Excel file from the Tally server's S:\Custom Uploads\ folder.
  • Treat every import as one-time. Assume it doesn't check for vouchers it already created: running the same dates or the same file twice can book them twice. The Easebuzz import also has a confirmed pagination bug (April settlements came in only partly), which invites re-fetches. This is the most likely cause of the Easebuzz gap (chapter 18).
  • It uses Tally's current date as the default. That's why forms showed December while Tally's date was 6-Dec-2026.

Tally On Cloud File Manager

Option 5 can only read a file that sits on the Tally server. File Manager is how a file on your laptop gets there.

Download report (Shiprocket XLS / Snapmint file)→File Manager → Custom Uploads= S:\Custom Uploads\ inside Tally →Option 5

  • If the import rejects the file, check the date format first. Format decision (Oct-2026): Shiprocket .xls, dates DD-Mon-YY (e.g. 28-Sep-26); Snapmint .csv, the older 27-column header with dates DD-MM-YYYY. Newer report formats are not backward compatible, and this is being worked on with the vendor. Send a rejected file to Hargun rather than editing it.

What we do here: monthly, upload the Shiprocket and Snapmint files to Custom Uploads and give the exact file name in option 5 (chapter 13).
S6

Tally Banking

The last link in every chain. Bank receipts clear the collection ledgers and Amazon Bank; payments clear creditors.

  • Concept: the statement is imported line by line. Each line is matched to an existing voucher, or a Receipt or Payment is created against the right ledger.
  • Routing: Easebuzz, Snapmint and Shiprocket credits → their Collection ledger. Amazon credits → Amazon Bank. Direct B2B receipts (Blinkit included) → the party ledger, against the bill reference. Supplier payments → the supplier. Inter-bank transfers are Contra. Per-bank notes are in chapter 9.
  • Rule: anything unknown is named to Hargun. Don't park it in Suspense, which already holds ₹12.6 L.
  • Format: Central Bank Excel needs headings on row 14. Upload via File Manager → Bank Statement New.
S7

The manual layer

What no plugin does: platform GST invoices, the Amazon expense JV, payroll and adjustments.

  • Platform invoices (Amazon ads and fees, Shiprocket, Easebuzz, Snapmint), as Purchase-Expense against each platform's control ledger (chapter 13, M4).
  • Amazon expense JV monthly: Dr Amazon Expenses (Creditors), Cr Cost of Advertising and settlement-posted FBA heads (chapter 6).
  • GST set-off and payment journals monthly (chapter 7, query to the CA).
  • Capital goods and monthly depreciation, booked directly in Tally, never through Tranzact (chapter 9b).
  • Provisions and other journals, and payroll.

FAQ

Questions that came up while the setup was documented, with their answers. Use the sidebar filter to jump to a topic.

Amazon

Why does Cost of Advertising show ₹34.6 L?

Settlements post each ad deduction to Cost of Advertising. The ads GST invoice books the same spend again to Amazon Ads (₹33.84 L Dr, the correct expense). The monthly JV that cancels the settlement side (template Journal 53, 30-Apr-26) was passed only for April. Pass it for May–Oct (chapter 6).

Why is Amazon Expenses (Creditors) ₹34.6 L Cr?

It is the other half of the same missing JV. Once the May–Oct JVs are passed it should be close to zero. If about ₹1 L Dr is left afterwards, an invoice is missing.

What exactly does the monthly Amazon JV do?

Dr Amazon Expenses (Creditors). Cr Cost of Advertising (its full balance), FBA Inbound Pickup Service, and the settlement part of FBA storage fee. April example: ₹5,82,428.14 = ₹5,36,027.65 + ₹33,680.50 + ₹12,719.99. Our plugin partner advised it, and it is correct: it stops settlement deductions being treated as expenses paid as-is.

May–Oct catch-up: what goes in?

Cost of Advertising ₹34,57,347.02, plus FBA Inbound Pickup Service ₹1,07,026.89, plus the settlement share of FBA storage. Check the other FBA heads for the same pattern: FBA storage fee ₹0.70 L, FBA Inventory Storage Fee ₹0.39 L, Partnered Carrier ₹0.16 L. Long-term fix: ask the plugin vendor to post settlement ad deductions straight to Amazon Expenses (Creditors).

Which Amazon reports, and from where?

MTR-B2C, MTR-B2B and STR come from GST Monthly Reports. The Settlement comes from Reports Repository (All Unified → Transaction → month; download once Status shows done). Ads invoices come from Advertising Invoice History, fee invoices from Tax Document Library. Links are in chapter 20.

In what order do I import Amazon reports?

MTR → STR → Settlement. Sales must exist before the settlement can knock them off.

The Amazon file has more than 10,000 rows.

Run option 2 again with rows 00001-10000, then 10001-20000.

The PAN on the option 2 form is wrong.

It is pre-filled from the company. Change it with F11 → More Details → PAN/CIN.

Why is TDS (Amazon) ₹77,802 hard to reconcile?

It mixes the 194-O credit Amazon deducts from settlements with the 194C TDS we deduct on ads invoices, which Amazon must refund. Move the ads part to TDS Receivable - 194C (Ads).

When does Amazon refund the ads TDS?

After the 26Q is filed on time, TRACES reflects it, and Form 16A is uploaded on Seller Central. If it is older than 6 months, raise a case.

Shopify, Easebuzz, Snapmint, Shiprocket

Do I book Shopify returns, RTOs or cancellations by hand?

No. The plugin adjusts refunds, RTOs and cancellations automatically from Shopify's data. A COD order older than 30 days in Shopify COD Receivable usually means an RTO the plugin missed, or a reference mismatch.

A day of Easebuzz payouts looks missing. Do I re-fetch?

How is TDS on a job-work bill handled?

Tranzact → Payments → Ledger (Consolidated) → split icon → TDS → %, on the pre-GST value. For example, 2% of ₹1,01,374.27 is ₹1,718.21. This creates one journal; approve it in Journal Entry and push it.

Which TDS section does Tranzact use?

Only 194C is set (TDS Payable - 194C). Professional fees (194J), rent (194I) and purchase of goods above the threshold (194Q) need a different section, so check every TDS journal before you push it.

A payment was "Marked Paid" in Tranzact.

Mark Paid always posts to Central Bank of India - Operating A/C, which doesn't exist in Tally, whichever bank actually paid. Book payments from the bank statement instead.
